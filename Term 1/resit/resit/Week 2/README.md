## 1. Project Overview

Silent Burnout Sentinel is an AI-powered workload assessment system designed to analyze employee activity patterns, workload indicators, meeting schedules, and screen-usage metrics to identify potential signs of excessive workload and burnout risk.

Built using **n8n workflow automation and OpenAI**, the system processes activity data, calculates workload metrics, identifies concerning patterns, and generates personalized recommendations.

The system produces a detailed assessment report and automatically delivers the results to the employee through Gmail.

The primary objective is to encourage proactive workload management, improve work-life balance, and promote employee well-being.

## 2. Problem Statement

In modern workplaces, employees frequently experience excessive workloads, prolonged screen exposure, continuous meetings, and insufficient breaks.

These patterns can contribute to stress, reduced productivity, fatigue, and potential burnout.

Traditional approaches often depend on employees voluntarily reporting their stress levels or managers manually identifying workload problems.

Silent Burnout Sentinel aims to provide a more proactive approach by analyzing available workload indicators and generating automated assessments.

## 3. Project Objectives

- Analyze employee workload and digital activity patterns.
- Calculate daily screen-usage and meeting-related metrics.
- Identify excessive workload and unusual activity patterns.
- Use AI to interpret workload indicators.
- Classify potential workload risk levels.
- Generate personalized well-being recommendations.
- Automatically deliver detailed assessment reports through Gmail.
- Support privacy-conscious and transparent workload analysis.

## 5. Workflow Components

The workflow consists of multiple connected processing nodes.

| Component | Responsibility |
|---|---|
| Employee Configuration | Collects employee name and email details |
| Screen Activity Preparation | Prepares screen-usage indicators |
| Calendar Activity Preparation | Prepares meeting and schedule indicators |
| Input Validation | Validates the available assessment data |
| Workload Metrics | Calculates workload statistics |
| Historical Analysis | Evaluates workload trends over multiple days |
| AI Analysis | Uses OpenAI to interpret workload patterns |
| Risk Classification | Identifies workload risk categories |
| Recommendations | Generates actionable well-being suggestions |
| Report Generation | Creates the final assessment report |
| Gmail Integration | Sends the report to the employee |

## 6. AI Integration

OpenAI acts as the intelligence layer of the system.

The AI receives structured workload metrics and historical indicators generated by the workflow.

It analyzes the information to identify:

- Excessive screen exposure.
- High meeting frequency.
- Extended working hours.
- Insufficient breaks.
- Repeated high-workload patterns.
- Potential workload imbalance.

Based on the available information, the AI generates a natural-language assessment and recommends practical improvements.

**AI Technology:** OpenAI API  
**Model:** GPT-4o-mini

The AI provides workload-related observations, not medical diagnoses or clinical burnout assessments.

## 7. Workload Risk Assessment

The system combines calculated workload indicators with AI-generated analysis.

The assessment can classify workload patterns into the following categories:

| Risk Level | Interpretation |
|---|---|
| Low | Workload indicators appear relatively balanced |
| Moderate | Some workload patterns may require attention |
| High | Repeated or excessive workload indicators need attention |
| Elevated | Persistent workload patterns warrant proactive intervention |

Risk classification is intended as a guidance mechanism rather than a clinical assessment.

## 8. Automated Email Reporting

One of the primary outputs of the workflow is an automatically generated Gmail assessment report.

The report can contain:

- Employee information.
- Screen activity summary.
- Meeting workload analysis.
- Daily workload statistics.
- Historical workload trends.
- AI-generated observations.
- Risk classification.
- Personalized recommendations.

The objective is to provide employees with an understandable summary of their workload patterns without requiring them to manually analyze the data.

## 10. Project Execution

### Prerequisites

- An n8n account.
- An OpenAI API key.
- Gmail OAuth2 credentials.
- Imported n8n workflow JSON.

### Setup Instructions

1. Download the workflow JSON file from this repository.
2. Open your n8n workspace.
3. Import the JSON workflow.
4. Open the employee configuration node.
5. Enter the employee name and email address.
6. Configure the OpenAI API authentication.
7. Configure Gmail OAuth2 credentials.
8. Verify the workflow connections and expressions.
9. Execute the workflow.
10. Check the configured Gmail inbox for the assessment report.

## 12. Privacy and Security Considerations

Employee activity information should be processed responsibly.

The system should follow these principles:

- Collect only the information required for workload assessment.
- Protect API credentials using n8n credentials.
- Avoid collecting private screen contents or personal messages.
- Restrict access to employee assessment reports.
- Obtain appropriate employee consent before collecting activity information.
- Define data retention and deletion policies.
- Never use workload indicators as the sole basis for employment decisions.

## 13. Current Implementation Scope and Limitations

This repository contains a workflow prototype demonstrating automated workload assessment.

**Important implementation details:**

- The current demonstration uses prepared sample activity data for screen-usage and calendar indicators.
- It does not independently monitor the employee's laptop, applications, or screen.
- Actual screen monitoring requires a separately installed and authorized data-collection component.
- Live Google Calendar analysis requires configured Google Calendar integration.
- AI analysis depends on valid OpenAI API credentials.
- Gmail delivery requires successful OAuth2 configuration.
- Risk classifications are indicative and are not medical diagnoses.

These limitations distinguish the current workflow demonstration from a fully deployed employee-monitoring platform.
